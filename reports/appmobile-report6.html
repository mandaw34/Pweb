Modul 6: State Management pada Aplikasi ResepKu (setState() dan Provider)

Modul VI: State Management (setState() dan Provider)

A. Pendahuluan

State management merupakan aspek krusial dalam pengembangan aplikasi mobile berbasis Flutter. State didefinisikan sebagai data yang dapat berubah selama siklus hidup aplikasi berjalan dan secara langsung memengaruhi tampilan antarmuka (UI). Pada Modul Praktikum VI ini, pembahasan difokuskan pada pengelolaan state lokal menggunakan setState() pada Stateful Widget untuk fitur jumlah porsi, serta pengelolaan state global menggunakan package provider (menggunakan ChangeNotifier dan MultiProvider) untuk fitur daftar resep favorit, badge, dan halaman Favorit secara terpusat.

B. Tujuan

  • Membuat state lokal dengan Stateful Widget dan setState() pada fitur jumlah porsi di halaman detail.
  • Menjelaskan keterbatasan state lokal ketika satu data dibutuhkan secara bersamaan oleh banyak widget dan halaman.
  • Membuat state global dengan package provider (ChangeNotifier dan MultiProvider) pada fitur resep favorit.
  • Membaca state global menggunakan context.watch, context.read, dan Consumer di berbagai halaman.

2. Pengamatan Bagian B: Eksperimen State Lokal

Berikut adalah jawaban dari tiga pertanyaan analisis terkait eksperimen penyimpanan status favorit menggunakan state lokal pada masing-masing tile:

  • a. Apakah ikon hati berubah? Mengapa?
    Ya, ikon hati berubah warna menjadi merah karena fungsi setState(() => isFavorite = !isFavorite) memicu pembaruan state lokal dan membangun ulang (rebuild) widget tile terkait.
  • b. Coba tampilkan jumlah resep favorit di judul AppBar HomePage. Apakah hal itu dapat dilakukan? Di class mana data isFavorite berada, dan apakah HomePage dapat membacanya?
    Hal tersebut tidak dapat dilakukan dengan mudah. Variabel isFavorite berada di dalam class privat RecipeTileState, sehingga widget HomePage selaku induk tidak dapat mengakses atau membaca state privat dari anak widgetnya secara langsung.
  • c. Buka halaman detail dari resep yang sudah difavoritkan. Bagaimana halaman detail dapat mengetahui bahwa resep tersebut favorit?
    Halaman detail tidak dapat mengetahuinya (ikon hati tetap kosong), karena status favorit tersebut hanya disimpan secara lokal dan terisolasi di dalam RecipeTile, sehingga tidak terbawa saat berpindah halaman.

4. Pertanyaan Analisis

  • a. Jawaban tiga pertanyaan pada Langkah B.2:
    Telah dijabarkan pada poin pengamatan Bagian B di atas, di mana state lokal terisolasi di dalam masing-masing tile dan tidak dapat dibagikan antarhalaman.
  • b. Mengapa jumlah porsi tetap menggunakan setState() dan tidak dimasukkan ke Provider?
    Jumlah porsi bersifat sementara dan hanya dibutuhkan secara lokal oleh halaman detail resep tersebut. Berdasarkan hasil pengujian skenario 6, ketika halaman detail ditutup, state lokal dibuang dan di-reset ke nilai awal, sehingga tidak memerlukan state global Provider.
  • c. Pemindahan ChangeNotifierProvider ke dalam HomePage:
    Jika ChangeNotifierProvider dipindahkan ke dalam HomePage (membungkus Scaffold), halaman Favorit yang dibuka melalui Navigator akan mengalami error ProviderNotFoundException karena posisinya berada di luar cakupan sub-tree widget tree provider tersebut.

C. Kesimpulan

Praktikum Modul VI berhasil diselesaikan dengan baik. Penggunaan state lokal setState() terbukti optimal untuk data yang bersifat sementara dan hanya digunakan pada satu widget (seperti pengaturan jumlah porsi), sedangkan state global menggunakan package provider sangat efektif untuk mengelola data bersama yang diakses oleh banyak halaman sekaligus (seperti resep favorit, badge, dan halaman Favorit). Pemahaman ini memberikan fondasi yang kuat dalam merancang arsitektur aplikasi mobile yang reaktif, interaktif, dan terstruktur.
